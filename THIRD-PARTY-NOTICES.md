`Gosf.Input.Automation.Native.x64.dll` backends are built into ignored
`artifacts/` directories from the input-only source in
`src/Gosf.Input.Automation.Native/core`. No compiled DLL is kept in the source
repository. That source
is derived from [op 0.4.8.3, commit 6d6b2854971ce3ae7da5bed62f915cb481ba57df](https://github.com/WallBreaker2/op/tree/6d6b2854971ce3ae7da5bed62f915cb481ba57df).

`licenses/op.txt`. The binding, C API, context, and hook exports were trimmed
to retain input functionality without the original capture and image modules.

LGPL-3.0 incorporates it; its presence does not by itself make the OP code GPL.

BlackBone is linked statically. The x86 and x64 link maps generated by the
current Release builds both contain `wow64ext.obj`. Before distributing these
binaries, provide the corresponding LGPL source and verify that recipients have
the materials and instructions needed to relink against a modified LGPL
component. The current package has not been verified to satisfy those
distribution requirements.

The automated release workflow now attaches a corresponding native source
archive containing this project's sources and the fetched BlackBone and MinHook
trees before pushing the NuGet package. Rebuild instructions, including local
dependency overrides for modifying the LGPL component, are in
`docs/NATIVE-REBUILD.md`. Release maintainers must review these materials against
the applicable distribution terms; the archive is not an independent legal audit.

Build the backends with `scripts/build-native.ps1`; the build records and link
maps are written under `artifacts/gosf-input-automation-native-x86` and
`artifacts/gosf-input-automation-native-x64`.
The x86 project exports undecorated input-hook aliases through
`hook-exports-x86.def`.
